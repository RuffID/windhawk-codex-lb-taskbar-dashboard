# Codex LB Taskbar Dashboard

Локальный мод Windhawk для Windows 11: процент usage на панели задач и popup
с аккаунтами, Reset и версиями codex-lb. Совместимость проверена с Windhawk 1.7.3.

## Источник истины и структура

- mod.wh.cpp в корне — основной файл: метаданные, описание, настройки, include и
  четыре коротких entrypoints. EditorWorkspace/mod.wh.cpp — временная рабочая
  копия Windhawk. Перед сборкой переносить содержимое основного файла в редактор;
  правки, сделанные в UI, возвращать в корневой файл до следующей работы/передачи.
- src/ — единственная реализация в .h, одна единица трансляции, namespace
  codex_dashboard. COM exports глобальные. Не создавать production .cpp/систему сборки.
- editor/ — настройка clangd; tests/ — C++ regression harness.
- README.md — короткое описание для пользователя и порядок установки/обновления.
- .clangd выбирает editor/compile_commands.json; .gitignore исключает кеши,
  локальную базу clangd, служебную папку Visual Studio .vs/ и двоичные результаты
  сборки. .git — служебные данные Git.

Абсолютный include-путь вручную задаётся только в @compilerOptions корневого
мода. Внутри проекта include относительные, .h имеют #pragma once и явные
зависимости без циклов. Общее состояние принадлежит core/state.h, watcher —
integration/xaml_tap.h. Не дублировать globals и не добавлять inline повсеместно.
Windhawk собирает stdin (-x c++ -) из Compiler; относительный include не
отсчитывается от EditorWorkspace. Не менять установку/расширение/компилятор.

## Работа и разрешения

- Изменять файлы только по явной просьбе; анализ/ревью сами по себе не разрешают правки.
- Делать необходимые точечные ручные изменения через apply_patch, без общего
  форматирования. Сохранять UTF-8 без BOM и CRLF, проверять кириллицу, U+FFFD
  и последовательности из четырёх вопросительных знаков.
- Предпочитать fail-fast; не скрывать первопричины запасными ветками.
- Не редактировать generated/build/dist вручную без прямой просьбы об этих файлах.
- Не запускать .ps1/.exe/тесты/приложения без отдельного разрешения на точную
  команду и файл; мод, Explorer, сеть, Docker и deployment не активировать без просьбы.
  Проверка компиляции должна учитывать stdin, cwd Compiler и параметры мода.
- Не выполнять Git-команды без просьбы о конкретной операции; init не разрешает
  add/commit/push. Не подключаться к БД и не выполнять SQL.
- Исключения для frontend tests и системных скриптов skill-creator из личных
  инструкций пользователя сохраняются, но к этому C++ моду не относятся.

## Документация вместе с изменениями

При изменении кода, тестов, конфигурации или состава файлов одновременно обновляй
AGENTS.md каждой затронутой рабочей папки: назначение файлов, зависимости,
поведение и способы проверки должны описывать итоговое состояние.
При создании новой рабочей папки сразу добавляй в неё AGENTS.md с её назначением.
Если изменились границы модулей/структура, обнови AGENTS.md родителей; если подключение или
пользовательское поведение — также корневой README.md и описание в mod.wh.cpp.
Не добавляй инструкции в .git, генерируемые кеши и build artifacts. Изменения
самого AGENTS.md не требуют рекурсивного обновления всех соседних инструкций.
